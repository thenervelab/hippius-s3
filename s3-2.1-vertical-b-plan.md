### B1 · inv-guard continuous asserter *(closes #3 · L 1–2 wk · THE BACKBONE — build first)*

  - **G1 single-leader+epoch** — `sum(drain_leader)`, `GET cephor:epoch`, allocator `Fenced` log; fail on ≥2 leaders, epoch decrease, or any `cephor:alloc:<id>` epoch < current after a tick. *(the R3/S10/S11 work hardens exactly this signal — see B3/B4.)*

  - **G4 sole-producer** — runtime SQL uniqueness on `(chunk_id, backend)` + the static inv-det audit *(already partially landed).* 
  - **G6 terminal monotonicity** — sampled diff of `cephor_replication_status`; fail on any `replicated→*` / `failed→*` transition.
  - G2/G5/G7/G8 — wire the predicate seams (G2 = George's SQL; G5 at-least-once-no-dup; G7 AEAD determinism; G8 reaper safety).
- **Acceptance:** breach → abort + JSONL event + non-zero exit; a clean run prints a G1–G8 pass table. Freeze the JSONL schema (seam #2).

### B2 · T4 allocator rigs A + B + R3 failpoint *(closes #7 · USER PRIORITY, hard gate · L 1–2 wk)*
Prove the allocator under failover, and **fix R3** — the lease-revalidation race.

- **R3 the bug** (`tick.rs:77-83`, confirmed): `run_tick` acquires the lease (epoch N), then `load_fleet → ceiling() (SLOW) → allocate → write_allocations(epoch N)` with **no lease re-read**. The Lua fence only rejects against *already-written* alloc keys, so a deposed leader (N) that finishes a slow `ceiling()` before successor (N+1) writes any key lands an epoch-N budget the fence lets through; an agent enforces it, briefly exceeding N+1's ceiling. Every existing fence test seeds the higher epoch first, so the window is never exercised.
- **Fix (robustness order):**
  1. **Register the epoch at the resource at election time** — bump a `cephor:epoch` resource watermark to N+1 the instant B wins, *before* any slow work (Chubby-sequencer / etcd `mod_revision`).
  2. **Fold the epoch into the Lua CAS conditioned on current `cephor:epoch`/`cephor:leader`**, not the last-written alloc value — reject any writer epoch below current.
  - A bare "re-read lease before write" is **insufficient** (irreducible check→write TOCTOU + the lower token reaching the resource first — FizzBee/Jepsen result). Don't ship that.
- **Rigs:** Rust `alloc_stress.rs` + compose (Rig A = toxiproxy redis-queues proxy — build the proxy here, reuse in B7; Rig B = multi-allocator failover).
- **Test (the gate):** failpoint/SIGSTOP at the `ceiling()`→`write_allocations` boundary; elect successor; release the paused leader; **assert the successor's resource REJECTED the stale write** (assert the rejection, not "no corruption"). This is the T4-C Tier-2 + new T2-1 case. Existing tests in `tick.rs` (`a_deposed_leader_tick_surfaces_the_fence…`) seed epoch-100 first — the new test must NOT, or it re-hides the window.

## Wave 1 — the scary gate + its neighbour

### B3 · R4 corrupt-state / alert-before-reclaim *(closes #14 · M 3–5 d · NON-OVERRIDABLE — silent live-object loss)*
The scariest gap. A persistent `ChunkMismatch` on a **live** object (`drain_part` → `partdrain.rs:437` cleanup + `mark_failed`) marks the part `failed`; then `reclaim_ssd` reclaims aged `failed` parts and deletes the **intact SSD source** — the last good copy, since the pool copy is corrupt. `failed` conflates "abandoned junk (safe to reclaim)" with "live object, corrupt pool copy (must NOT reclaim)."

- **Fix:** add a distinct **non-reclaimable `corrupt` state** (or alert-before-reclaim) so a servable object's last copy is never self-destructed. `reclaim_ssd` reclaims `failed` (+ George's servability predicate) but **never** `corrupt`; a `corrupt` mark raises a distinct alarm and holds the SSD source for a human/monitored recovery.
- **⚠ Seam #1** — this is the same `reclaim_ssd` delete point George's WI-20b touches. Co-design the state machine (`pending`/`draining`/`replicated`/`failed`/**`corrupt`**) and the servability predicate in one sitting before either change lands. The migration adds the enum value; agree who owns it (drain migration vs hippius_s3 migration).
- **Test:** a live (servable) part with a persistent pool `ChunkMismatch` → marked `corrupt`, NOT `failed`; `reclaim_ssd` leaves its SSD source intact + a distinct alarm fires; assert the SSD bytes survive (checklist #14: "distinct alarm before unlink").

## Wave 2 — correctness fixes + resilience

### B5 · C13 breaker — split `Persist` *(latent bug · unit `#C13`)*
`is_ceph_write_failure` (`partdrain.rs:331-337`) keys on `ErrorKind`, not `DrainStep`. But **`DrainStep::Persist` is overloaded** across SSD-reads (`list_chunks:390`, `part_meta:398`, `chunk_source:418`, `meta_source:448`) AND Ceph-writes (`persist_chunk:424`, `write_meta:451`, `finalize_part:455`). So a local **SSD-read EIO** reads as a Ceph-write failure and trips the node-global breaker, wedging drain of a healthy pool.
- **Fix:** split the step so the classifier can tell an SSD-side read from a Ceph-side write — e.g. `DrainStep::{SsdRead, CephWrite, Hash, Cleanup, Unlink}`, and `is_ceph_write_failure` returns true only for `CephWrite`/`Hash`/`ChunkMismatch`, never `SsdRead`/`Unlink`. **Don't just exempt `Unlink`** (the todo's explicit warning) — `Persist`-tagged SSD reads are the bigger hole.
- **Test:** an EIO tagged as an SSD read → `Deferred`, not `CephFailure` (extend `is_ceph_write_failure_only_for_real_pool_io_and_mismatch`).

### B6 · C11 uuid-suffix localfs temp *(G5/G6/F1)*
`.tmp-<name>` is not uuid-suffixed (`store.rs:395`, `localfs.rs:271`). Fenced by `claim_seq` today, but real under low lease + slow Ceph (intra-node double-drain + tmp-collision). Suffix the temp with a uuid4 (mirror the api-side `.tmp.<uuid>` pattern). Small; test the two-writers-same-part case.

### B7 · readiness/C8 + R5 zero-throughput alert — the liveness pair *(C8: F4/S7/R5 · R5 closes #15 · S–M)*
Two complementary blind spots to a wedged drain — do together.
- **C8 readiness probe:** liveness today is heartbeat-only (`runtime.rs:490-509` touches liveness before the disk probe), so a **hung CephFS stalls draining while the pod stays "healthy."** Add a *readiness* probe that goes NotReady when the drain loop is wedged (breaker open past cooldown, or no successful drain despite backlog), so k8s pulls the node from rotation. Careful: don't flap a legitimately-long backlog drain (the heartbeat comment already notes drain can run long).
- **R5 zero-throughput-with-backlog alert:** a total stall (breaker open / agent dead) produces **zero lag samples**, so the lag-histogram SLO looks *healthy* while SSD fills. Add a SQL/Redis-derived `throughput==0 ∧ backlog>0` alert **independent of the lag histogram**.
- **Test:** force a stall (breaker open or SIGSTOP the drain) with backlog > 0 → readiness flips NotReady AND R5 fires. F4/agent-kill exercises both in Phase 2.

### B8 · C7 full-jitter backoff *(F3/F6 recovery)*
Fixed sleeps (`runtime.rs:97,179,323`, `run.rs:103`; `BREAKER_COOLDOWN:44`) → thundering herd on Redis/PG/Ceph recovery. Wrap the periodic/backoff sleeps in full-jitter. Keep it centralized (one jittered-sleep helper) so it's testable and consistent. *(Defer AIMD smoothing per WI-18 until T5 load data.)*
