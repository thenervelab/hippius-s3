# PHASE 1 — Correctness (data path)

> Interaction warning: **WI-1, WI-2, WI-3 all edit the same `drain_part` copy region (`partdrain.rs:338-362`).** Implement them as **one PR**: WI-1's completeness guard goes in first (before `let (first,last)`), then WI-2's full-readback loop *is* WI-3's retry loop (one edit, not two).

## WI-1 — Completeness check before commit/unlink  [P1, data-loss class · ~1 day]
**Files:** `core/apipart.rs`, `core/lib.rs`, `core/partdrain.rs`, `agent/localfs.rs`.
**Why:** `drain_part` trusts `list_chunks` and never parses `meta.json`'s `num_chunks`, so a part with meta present but a missing/zero-length interior chunk is committed `Replicated` and the SSD source (only complete copy) deleted → silent truncation.

**Change:**
- **`meta.json` schema** (written by `hippius_s3/cache/fs_store.py:329`): `{"chunk_size":int,"num_chunks":int,"size_bytes":int}`. Parsing lives in the **agent** (`serde_json` is an agent dep; core doesn't enable serde).
- New plain value type in `apipart.rs` (no serde): `pub struct PartMeta { chunk_size: u64, num_chunks: u32, size_bytes: u64 }`; export from `lib.rs`.
- New `PartSource` trait method (`partdrain.rs`): `fn part_meta(&self, part: &PartKey) -> impl Future<Output = io::Result<PartMeta>> + Send;`
- `LocalSsd` impl (`localfs.rs`): read `meta.json`, deserialize a private `MetaJson` serde struct; a **malformed** meta → `io::ErrorKind::InvalidData` (non-benign, trips breaker — a corrupt manifest is real); a **missing** meta → `NotFound` (already benign).
- New `PartDrainError::IncompleteSource { declared: u32, present: u32 }`; add it to `is_benign_deferral()` → **defer, don't hard-fail** (meta-last ordering means a present-meta/missing-chunk is a concurrent overwrite/clean, i.e. transient; deferring keeps the SSD copy, never commits, never unlinks; a genuinely-stuck part is caught by age-based `ssd_reclaim`).
- Guard in `drain_part`, immediately after `list_chunks` (`partdrain.rs:338`):
  ```rust
  let meta = ssd.part_meta(part).await.map_err(PartDrainError::io(DrainStep::Persist))?;
  let present = u32::try_from(chunks.len()).unwrap_or(u32::MAX);
  let complete = present == meta.num_chunks
      && chunks.iter().enumerate().all(|(i, c)| c.get() == u32::try_from(i).unwrap_or(u32::MAX));
  if !complete { return Err(PartDrainError::IncompleteSource { declared: meta.num_chunks, present }); }
  ```
  (`list_chunks` returns ascending indices, so the `enumerate` equality verifies the exact contiguous set `{0..num_chunks}` — catches a short count *and* a hole like `{0,1,3}`.)

**Fixture fix (required):** `seed_ssd_part` (`localfs.rs:663`) hardcodes `num_chunks:1` — every multi-chunk test breaks the new gate until it writes `num_chunks: chunks.len()`.

**Tests:** `partdrain.rs` — extend the in-memory `Fakes` with `declared_chunks: Option<u32>` + a `part_meta` impl + a `declare_chunks(n)` builder; add `an_incomplete_part_defers_without_committing_or_unlinking` and `a_missing_interior_index_is_caught_even_when_the_count_matches`; extend the benign-deferral test. `localfs.rs` — a real-FS `end_to_end_drain_of_a_part_whose_meta_overdeclares_defers_and_keeps_the_ssd_copy`.

**Acceptance:** a part is never committed `Replicated` unless every declared chunk `0..num_chunks` is present; a truncated part defers with the SSD copy intact and nothing in the pool.

## WI-2 — Interior-chunk verification policy  [P1 · ~½ day, folded with WI-3]
**Files:** `core/partdrain.rs`.
**Why:** only first/last chunks are byte-verified (`partdrain.rs:347`); the "content-addressed → trust interior" comment is factually wrong (path-addressed; no re-drive after `Replicated`), so a torn interior pool write is committed unverified.
**Change — recommended option (a), full per-chunk readback:** replace the sampled `if Some(index)==first||==last` condition with an unconditional `chunk_hash` readback+compare for **every** chunk; delete the `let (first,last)=…` line; rewrite the loop comment to state "every chunk byte-verified" and drop the false rationale. (Option (b) — keep sampling, only fix the comment — is documented as the cheaper, weaker alternative; recommend (a): the independent `PartPool::chunk_hash` exists precisely for this and the cost is one extra slow-tier read per chunk.)
**Tests:** replace `a_corrupt_interior_chunk_is_not_caught_by_the_sampled_readback` with its inverse `…is_caught_by_full_readback`; rename the last-chunk test accordingly.
**Acceptance:** a corrupt interior chunk is caught, marks the part `Failed`, and never deletes the SSD copy.

## WI-3 — Guard + bounded-retry `mark_failed`  [P2 · ~½ day, folded with WI-2]
**Files:** `core/store.rs`, `core/partdrain.rs`. No migration (`claim_seq` already exists).
**Why:** `mark_failed` (`store.rs:581`) is unguarded — a fenced stale claimant hitting a mismatch flips a *live* re-claimed part to `failed`; and a *spurious* transient mismatch terminally discards a healthy part (pool copy removed, SSD reclaimed after grace).
**Change:**
- Mirror `mark_replicated`'s guard on `mark_failed`: `... SET status='failed', updated_at=now(), claimed_at=NULL WHERE object_id=$1 AND version=$2 AND part_number=$3 AND status='draining' AND claim_seq=$4`. **0 rows = benign no-op** (not `PartClaimLost`) — `mark_failed` authorizes no unlink, so a fenced claimant's no-op is safe and avoids surfacing a `Store` error that would (pre-WI-10) trip the breaker; also makes it idempotent.
- Bounded copy-retry in `drain_part`: `const CHUNK_COPY_ATTEMPTS: u32 = 3;`. Wrap the persist+readback (from WI-2) in a retry loop; only after exhausting attempts call `mark_failed` + `remove_part` + return `ChunkMismatch`. Re-persist on retry is safe (`copy_into` writes a fresh `.tmp` + atomic rename).
**Tests:** `store.rs` `mark_failed_by_a_fenced_stale_claimant_does_not_fail_the_live_part` (`#[sqlx::test]`); `partdrain.rs` `a_transient_torn_copy_is_recovered_by_the_bounded_retry` (fake that corrupts only the first N attempts). Existing `mark_failed_*` and `a_corrupt_chunk_copy_marks_failed_*` still pass.
**Acceptance:** a transient mismatch recovers via retry; a persistent one fails after N; a fenced claimant can't fail a live part.

## WI-15 — Ancestor-dir fsync  [P2 · ~½ day]  *(separate PR — different code region)*
**Files:** `agent/localfs.rs`.
**Why:** `finalize_part` (`localfs.rs:434`) fsyncs only the part dir; the new version/object dir entries linking it into the tree aren't fsync'd → a crash after `mark_replicated` can strand the part (row says `Replicated`, dir unreachable, nothing rebuilds it).
**Change:** in `finalize_part`, after the part-dir `sync_parent_dir`, also `sync_parent_dir` the version dir, object dir, and root (idempotent, cheap next to per-chunk data fsyncs). **Alternative:** if the pool is *always* CephFS (MDS-journals namespace ops synchronously), document that assumption on `sync_parent_dir` and leave as-is — but its own doc says the behavior is *unverified* on network mounts, so the ancestor-fsync is the safe default until staging measures it.
**Tests:** `finalize_part_fsyncs_the_new_part_version_and_object_dirs` (fresh deep tree; second finalize is a no-op).
**Acceptance:** `finalize_part` fsyncs the full new ancestor chain; existing e2e drain tests still pass.

## WI-6 — Decay-on-`Err` in the allocation pull (R1)  [P1 · ~½ day]

# PHASE 2 — Observability & operability

> Land order within phase: **WI-7 (exit code) → WI-5 (liveness) → WI-4 (metrics)** — smallest/zero-dep first, largest/new-deps last. All additive, none touch the data path.

## WI-7 — Non-zero exit on worker fault  [P1/P2 · ~2 hrs]
**Files:** `agent/main.rs` (+ `allocator/main.rs` for symmetry).
**Why:** `main` returns `Ok(())` discarding the `RunReport`; a panicked worker → orderly shutdown → **exit 0** → no CrashLoopBackOff, no alert.
**Change (lint-safe — `exit=deny` bans `process::exit`):** change agent `main` return to `Result<ExitCode, StartupError>`. Add a pure classifier (test on the `bool`, not `ExitCode` which isn't `PartialEq`):
```rust
fn faulted(r: &RunReport) -> bool { matches!(r.trigger, ShutdownTrigger::WorkerExited(_)) || !r.clean }
// main: Ok(if faulted(&report) { ExitCode::FAILURE } else { ExitCode::SUCCESS })
```
Allocator has no supervisor (single tick loop; per-tick faults already logged-and-retried) — change its `main` to `Result<ExitCode, StartupError>` returning `SUCCESS`; startup errors already exit nonzero via `Err`. **Call this out** so the missing FAILURE path isn't mistaken for an omission.
**Tests:** `faulted()` unit tests — `Signal+clean→false`, `WorkerExited→true`, `Signal+!clean→true`.
**Acceptance:** a worker panic exits nonzero → pod restarts with a fault signal.

## WI-5 — Liveness probe via heartbeat file  [P1 · ~½ day]
**Files:** `agent/runtime.rs`, `agent/main.rs`, `allocator/run.rs`, `allocator/main.rs`, both manifests. New `health.rs` (not feature-gated — must work in `--no-default-features`).
**Why:** neither binary has a liveness probe or inbound health endpoint; a *hung* (not crashed) tokio runtime stays `Running` → silent permanent per-node upload outage (sole producer).
**Change (file approach — zero deps, vs an axum/hyper server which pulls `axum`+`hyper`+`tower`+a port+a task):**
- `pub fn touch_liveness(path: &Path) { let _ = std::fs::write(path, b"ok"); }` (best-effort; a transient FS blip must not kill a healthy process).
- Env `CEPHOR_LIVENESS_FILE` (agent default `/tmp/hippius-drain-agent.alive`, allocator `/tmp/…-allocator.alive`).
- **Agent:** add `with_liveness(PathBuf)` builder + `liveness_path: Option<Arc<PathBuf>>` field to `AgentRuntime` (do **not** add a `PathBuf` to `RuntimeConfig` — it derives `Copy`). Touch at the **start** of each heartbeat tick (before `heartbeat_once`, so a statvfs early-return doesn't stall the signal). Cadence = `CEPHOR_HEARTBEAT_POLL_SECS` (10s). Fallback if you want liveness decoupled from the opt-in heartbeat worker: touch in the always-spawned `run_drain` loop.
- **Allocator:** touch at the top of the `run_allocator` loop (per-tick, ~2s) via the `Observability` bundle.
- **k8s exec probe** (bookworm-slim has GNU `stat`), both containers:
  ```yaml
  livenessProbe:
    exec: { command: ["sh","-c","f=/tmp/hippius-drain-agent.alive; test -f \"$f\" && [ $(( $(date +%s) - $(stat -c %Y \"$f\") )) -lt 40 ]"] }
    initialDelaySeconds: 30   # allocator: 20 (covers migrations)
    periodSeconds: 20         # allocator: 15
    timeoutSeconds: 5
    failureThreshold: 3
  ```
  Agent threshold 40s (10s cadence), allocator 30s (2s cadence).
**Tests:** none meaningful for the FS touch; the probe is validated on staging.
**Acceptance:** a wedged runtime fails liveness and k8s restarts the pod.

# PHASE 3 — Drain hardening / DB & infra hygiene

## WI-8 — Coordination Redis eviction (finding 3)  [P1 · interim ~1 day, permanent = topology]
**Why:** `cephor:*` coordination state lives on `redis-queues` (`redis-statefulsets.yaml:225`, `allkeys-lru`, 2GB). `cephor:epoch` (`INCR`, no TTL, `coordination.rs:52`) can be LRU-evicted → next takeover `INCR`s from absent → resets to 1 → re-issues spent epochs → the F4 fence mis-fires → allocator deadlock. Per-key TTL cannot fix this under `allkeys-lru`.

**(a) INTERIM — durable epoch floor (code, no infra):**
- Migration `0010_epoch_floor.sql`: single-row `cephor_epoch_floor (id bool PK CHECK(id), epoch bigint, updated_at)`, seeded 0.
- `Store::epoch_floor() -> u64` and `Store::bump_epoch_floor(epoch)` (monotonic `GREATEST`).
- `Coordinator::ensure_epoch_floor(floor)` — a Lua `SET` that only raises: `if floor > tonumber(GET or 0) then SET floor end`.
- Allocator startup (`allocator/main.rs`, after `Coordinator::connect`): `let f = store.epoch_floor().await?; coordinator.ensure_epoch_floor(f).await?;`.
- On every fresh win (`run.rs` `Led` arm): `store.bump_epoch_floor(plan.epoch).await` best-effort (log-on-err). Needs `plan.epoch` exposed from `TickOutcome::Led` + `&Store` in `run_allocator` (see the shared signature churn).
**Tests:** `ensure_epoch_floor` raises absent/low, leaves higher (redis-gated); `epoch_floor`/`bump_epoch_floor` monotonicity (`#[sqlx::test]`).

**(b) PERMANENT — dedicated `noeviction` coordination Redis (topology, Phase 7 decision):**
- New `redis-cephor` Service+StatefulSet (`redis-statefulsets.yaml`, mirror `redis-queues`) with `--maxmemory 256mb --maxmemory-policy noeviction --appendonly yes --appendfsync everysec`. A separate **logical DB** does **not** work (`maxmemory-policy` is server-global) — must be a separate instance.
- Add `CEPHOR_REDIS_URL` to `hippius-s3-secrets` (`redis://redis-cephor:6379`); new config field on both crates; agent builds a **second** `ConnectionManager` for the `Coordinator` (the `redis-queues` one stays for the `RedisEnqueuer` — the split is the point: enqueue on LRU, coordination on noeviction); allocator `Coordinator::connect(&config.coordination_redis_url, …)`. Manifests add `CEPHOR_REDIS_URL` via `secretKeyRef`.
- When (b) ships, (a)'s PG floor stays as defense-in-depth (survives AOF corruption / fresh PVC).
**Acceptance:** coordination survives redis memory pressure/eviction (WI-16 Test 3 + Phase-4 eviction chaos); epoch never regresses.

## WI-10 — Breaker error-domain (finding 9)  [P2 · ~½ day]
**Files:** `core/partdrain.rs`, `agent/worker.rs`.
**Why:** `worker.rs:168` classifies any non-benign `Err` as `CephFailure`, so a `Store`/`PartClaimLost` (Postgres/claim domain) trips the node-global Ceph breaker on a healthy pool.
**Change:** add `PartDrainError::is_ceph_write_failure()` → true only for non-ENOENT `Io` and `ChunkMismatch`; false for `Store`/`Enqueue`. Worker classification becomes tri-domain: benign → `Deferred`; ceph-write → `CephFailure`; else (store/claim) → `Deferred` (breaker untouched) but **release the part** (not `defer_part` with backoff) so it retries next poll. Keep `is_benign_deferral` as-is (it correctly excludes `Store`). Keep `DrainCycleError::is_deferral` keyed on `is_benign_deferral` so a PG outage still halts the burst (correct — don't spin on a dead DB).
**Tests:** force a `PartClaimLost`, assert `failed==0`, `deferred==1`, breaker still `allows`, part `Pending`; unit-test `is_ceph_write_failure` truth table.
**Acceptance:** a Postgres blip / claim loss never opens the Ceph breaker.

## WI-12 — `HIPPIUS_UPLOAD_BACKENDS` from secret (finding 11)  [P2 · ~1 hr]
