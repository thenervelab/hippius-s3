## 1. TL;DR

The drain's **core engineering is solid** — the delete-before-durable data path is closed on the normal paths, several past bugs are genuinely fixed (zombie double-commit, benign-deferral breaker), and the allocator math + producer→consumer wire contract are proptested/byte-verified. But it is currently **flying blind** (no metrics, no probes, no restart-on-fault), **untested where it's riskiest** (coordination), and **on the critical path with no fallback** (hard cutover — see §2).

**Five must-fix items before we trust this in production:**

1. **Data integrity** — the drain deletes the only good (SSD) copy without checking the part is whole against `meta.json`, and byte-verifies only the first/last chunk. A missing/torn interior chunk can be committed "Replicated" and the good copy deleted. *(WI-1, WI-2)*
2. **Coordination runs on a Redis that can evict its own fence** (`allkeys-lru`; the epoch counter has no TTL) → allocator deadlock under memory pressure, i.e. during the incident the drain exists for. *(WI-8)*
3. **CI is green but runs zero coordination tests** — no Redis in the job; ~12 fencing/election/lease tests skip silently. *(WI-16)*
4. **No liveness probes / health endpoint** — a hung pod = silent permanent per-node upload outage. *(WI-5)* + a **faulted worker exits 0** (no CrashLoopBackOff). *(WI-7)*
5. **Decay-on-`Err`** — the agent keeps draining at full rate into a degraded Ceph during a Redis outage. *(WI-6)*

Plus a cluster of P2s (breaker wedging in `Probing`; non-Ceph errors tripping the Ceph breaker; `mark_failed` discarding a healthy part; `HIPPIUS_UPLOAD_BACKENDS` hardcoded → silent under-replication; ancestor-dir fsync; O(N) reconciler; unpruned terminal rows) and P3 polish.

**None of the P1s are rewrites** — a completeness check, a Redis policy, a CI service, two probes, and an exit code. The realistic pre-prod punch list is a few days of work, sequenced below, starting with an **immediate hardening batch** that makes the *current* staging soak trustworthy.

## 2. Critical context — the hard cutover

**Verified:** `HIPPIUS_DRAIN_GATED_UPLOAD_ENABLED` exists only in old audit docs — not in any `.py`/`.rs`/`.yaml`. `put_object_endpoint.py:198-211` + `multipart.py:1072-1081` **unconditionally** stop PUT-time enqueue and only persist the object address; the drain reads it and produces the upload after replication.

**Consequence:** on staging *right now* the Rust drain is the **sole upload producer, with no fallback.** If the drain stalls on a node, that node's uploads stop. So the old "most bugs are latent until the flag flips" framing is dead — **every availability finding is live today**, and the Phase 1/2 P1s are staging-stability fixes, not just prod gates.

**Prod note:** there are **no prod drain manifests yet** (staging-only). At prod cutover the drain must ship *before/with* the api image that stops PUT-enqueue, or prod uploads stall.

## 3. Findings

Severity **P1/P2/P3** · **NEW** = surfaced by this audit · **DOC** = previously documented, still open · **FIXED** = verified resolved. Each maps to a work item in §5.

### P1 — Data integrity

- **F1 [NEW] Completeness check missing before commit/unlink.** `partdrain.rs:338-388` — trusts `list_chunks`, never parses `meta.json`'s `num_chunks`; a present-meta/missing-interior-chunk part is committed `Replicated` and the SSD source deleted → silent truncation. Mitigated by the api writing meta *last* (happy path safe), but the delete is irreversible and the check is cheap. → **WI-1**
- **F2 [NEW] Interior chunks committed unverified.** `partdrain.rs:330-362` — only first/last sampled; the "content-addressed" rationale is factually wrong (path-addressed; no re-drive after `Replicated`), so a torn interior pool write commits unverified. → **WI-2**

### P1 — Coordination / availability

- **F3 [NEW, 2 agents] Coordination on an `allkeys-lru` Redis can evict its own fence.** `coordination.rs:52` (`INCR cephor:epoch`, no TTL) + `redis-statefulsets.yaml:225` (`allkeys-lru`, 2GB). Eviction of the epoch counter resets it to 1 → re-issues spent epochs → the F4 fence mis-fires → the legit leader is permanently fenced → allocator deadlock, fleet decays to floor. Worst under the memory pressure the drain targets. → **WI-8**
- **F4 [NEW] CI runs zero coordination tests.** `test-and-lint.yml:232-247` — postgres service but no Redis, `CEPHOR_TEST_REDIS_URL` never set → ~12 fencing/election/lease/decay tests skip silently green. Riskiest layer, least verified. → **WI-16**
- **F5 [NEW] No liveness probe / health endpoint on either binary.** A *hung* (not crashed) tokio runtime stays `Running` → silent permanent per-node upload outage (sole producer). → **WI-5**
- **F6 [DOC, R1, 3 agents] Decay-on-`Err`.** `runtime.rs:280` — the `Err` arm holds the last budget forever; only `Ok(None)` decays. → **WI-6**
- **F7 [DOC, R6] Faulted worker exits 0.** `main.rs:93-95` returns `Ok(())` regardless of the `RunReport`; a panicked worker → orderly shutdown → exit 0 → no CrashLoopBackOff, no alert. → **WI-7**

### P2 — Correctness & resilience

- **F8 [NEW] Breaker can wedge permanently in `Probing`.** `enforce.rs:78-89` — no deadline; a cancelled/unwound probe drain (breaker-neutral `release_permit`) leaves it stuck → denies all drains until restart. → **WI-9**
- **F9 [NEW] Non-Ceph errors trip the Ceph breaker.** `worker.rs:168-172` — a `Store`/`PartClaimLost` (Postgres/claim domain) maps to `CephFailure` and can open the node-global breaker on a healthy pool. → **WI-10**
- **F10 [NEW] `mark_failed` unguarded + discards pool copy with no retry.** `store.rs:581` + `partdrain.rs:349-360` — a fenced stale claimant can fail a live part; a spurious transient mismatch terminally discards a healthy part. → **WI-3**
- **F11 [DOC, PR-199 P3] `HIPPIUS_UPLOAD_BACKENDS` hardcoded on the drain.** `drain-agent-daemonset.yaml:99` literal vs secret-sourced Python workers; adding a backup backend silently under-replicates (never enqueued → janitor replication gate never clears → unbounded cache growth). → **WI-12**
- **F12 [NEW] Ancestor-dir fsync gap.** `localfs.rs:434` fsyncs only the part dir; a crash after commit can strand the part (row `Replicated`, dir unreachable, nothing rebuilds). → **WI-15**
- **F13 [NEW] Redis hang wedges the loops.** `coordination.rs` `ConnectionManager` has no response timeout; a half-open connection hangs the tick/heartbeat/alloc-pull loops (error-retry never fires on a hang). → **WI-11**
- **F14 [NEW] No allocator-before-agent ordering gate.** `kustomization.yaml` — agents CrashLoop on a fresh-namespace apply before the allocator migrates the `cephor_*` schema. → **WI-14**
- **F15 [NEW] O(N) reconciler `status()`.** `reconcile.rs:158` — one SELECT per scanned part per cycle; the reconciler is the sole drain trigger. → **WI-13**
- **F16 [DOC, R4] Terminal rows never pruned.** `cephor_replication_status` grows unbounded, bloating the hot `claim_part`/reconcile scans. → **WI-17**
- **F17 [NEW] Silent-failure observability gaps** — breaker-open logged at `debug` (same path as normal rate-limit); stuck-defer indistinguishable from backpressure; worker-faulted exit 0. → covered by **WI-4** (metrics) + **WI-7**.

### P3 — Polish / hardening (→ WI-18)

AIMD burst-on-probe-recovery (`alloc.rs:303`); blind probe never `Critical` (`probe.rs:133`); pods run as root / no `securityContext` (allocator could run non-root); `Recreate`+slow-pull exceeds the 15s alloc TTL (per-deploy throttle); the `AlreadyReplicated` recovery path is structurally unreachable (SSD-orphan leak); `O_NOFOLLOW` on SSD opens (F5-legacy); heartbeat/skipped-replicated/allocator-tick failures log-only; R5 (defer-cap, AIMD EWMA+dead-band+safe-floor, full-jitter backoff, worker **readiness** probes); R6 (`write_allocations` lease revalidation, `arithmetic_side_effects`+`indexing_slicing` lints).

### 3.x What's already solid (confirmed FIXED / SAFE — do not re-litigate)

- **Delete-before-durable closed on the normal/common-failure paths:** copy → fdatasync → sample-verify → persist meta last → dir-fsync → **enqueue → commit → unlink** (`partdrain.rs:373-387`); `PartVerified` makes commit-before-verify a compile error. (F1/F2/F12 are the residual edges.)
- **F4 zombie double-commit FIXED** (`claim_seq` fences `mark_replicated`); **F18 FIXED** (`mark_failed` clears `claimed_at`); **PR-199 P1 FIXED** (benign-deferral breaker classification).
- **Producer→consumer wire contract byte-verified both directions** (shared golden fixture; consumer `run_arion_uploader_in_loop.py:125`).
- **Allocator/token-bucket/`decay_rate` math sound** (no over-allocation, no div-by-zero, `u128` intermediates, proptested); **no fail-open ceiling** (probe fails safe to floor).
- **Split-brain fence logic sound** — except the LRU-eviction hole (F3).
- **Claim/lease correctness sound** (no NULL-`claimed_at` wedge; node-scoped; stale-claim reclaim); **`ssd_reclaim` fail-safe**; **config fail-fast, no missing-env crash-loop**; **workspace lints real + enforced**.

## 4. Road to production

Sequenced; each phase gates the next. Nothing ships to prod until Phase 7 signs off. Findings from §3 are slotted into the phase that owns them (`➕` = audit addition to the original plan).

**Phase 1 — Correctness (staging).** Append drain-direct fix (#217); soak the merged janitor abandoned-reclaim (#214); **R1 decay-on-`Err`** (F6/WI-6); **➕ data-completeness + interior-verification + `mark_failed` guard** (F1/F2/F10 → WI-1/2/3); **➕ ancestor-dir fsync** (F12/WI-15).
*Gate:* drain-direct invariant holds; Redis-outage decays to floor; **a part is never committed `Replicated` unless every declared chunk is present and verified**; a transient mismatch never discards a healthy part.

**Phase 2 — Observability & operability.** **R2 metrics + "S3 Drain" dashboard + instrument the Python loops** (F17/WI-4); **➕ liveness probe + health signal** (F5/WI-5, pulled forward — liveness catches the hung-pod outage; *readiness* stays in Phase 3); **➕ non-zero exit on worker fault** (F7/WI-7).
*Gate:* throughput, replication lag, backlog, failures, reclaimed, **coordinator/leader + epoch health**, DLQ depths visible on the staging dashboard; a hung or panicked pod restarts and alerts.

**Phase 3 — Drain hardening / DB & infra hygiene.** R3 batch reconciler (F15/WI-13); R4 terminal-row GC (F16/WI-17); R5/R6 polish (WI-18); **➕ coordination-Redis eviction interim** (F3/WI-8a); **➕ `Probing` deadline** (F8/WI-9); **➕ breaker error-domain** (F9/WI-10); **➕ Redis timeouts** (F13/WI-11); **➕ backends-from-secret** (F11/WI-12); **➕ allocator-before-agent ordering** (F14/WI-14).
*Gate:* bounded PG churn; no unbounded backlog or cache growth; the fence survives Redis memory pressure; the breaker can't wedge and doesn't trip on non-Ceph faults.

**Phase 4 — Scale validation (staging + chaos).** **➕ Prerequisite: CI Redis + coordination tests** (F4/WI-16) before chaos. Then the 1GB MPU benchmark + replication-lag experiment, burst/SSD-fill, and the chaos matrix (kill node, redis **blip + eviction + hang**, ceph degradation) with an **end-to-end checksum "no data loss" gate** (WI-19).
*Gate:* throughput acceptable; lag bounded; every failure self-recovers; **byte-for-byte object integrity confirmed by checksum** after each scenario.

**Phase 5 — ATS edge auto-caching (staging).** Deploy the auth-probe ATS config + visibility demotion; prove zero private-data leak on a cache hit and cross-node gap bridging; gated default-cacheable flip. Security linchpin `doc_in_cache_skip_dns=0` (matches the scale-hardening Tier-5 auth-leak concern). *Gate:* zero leak proven; per-hit auth latency acceptable. *(Outside the drain scope.)*

**Phase 6 — Prod readiness.** Rollout/rollback runbooks (incl. WI-14 ordering + "drain ships before the PUT-enqueue-off api image"); alerting: drain lag, SSD pressure, DLQ growth, coordinator **leader-loss + epoch/fence anomaly**, ATS auth-probe errors, **➕ worker-faulted-exit (WI-7), breaker-open + stuck-defer (WI-4), cache-growth/replication-gate (WI-12)**; confirm the durable backup path intact **and that the drain's resolved backend set == the secret (WI-12)**; ATS never treated as durability. *Gate:* runbooks + alerts + rollback rehearsed on staging.

**Phase 7 — Prod network topology decision meeting.** SSD ingest nodes (count/sizing vs lag+pressure); taints/isolation (PG-NVMe off ingest; dedicated SSD nodes; nodeAffinity); scaling (DaemonSet + allocator singleton placement, api-local replicas, graceful node add/drain); ATS fleet+cutover; **➕ dedicated `noeviction` coordination Redis (WI-8b)** — a topology decision, not a code change. *Gate:* signed-off topology + cutover runbook.

## 5. Implementation plan

Each WI is self-contained. **Interaction warning: WI-1/2/3 edit the same `drain_part` copy region — one PR.** The shared `run_allocator` signature change (WI-4/WI-8a/WI-17) is a one-time churn — see §7.

### PHASE 1

**WI-1 — Completeness check before commit/unlink** · P1 · ~1d · `core/apipart.rs,lib.rs,partdrain.rs`, `agent/localfs.rs`
`meta.json` = `{"chunk_size":int,"num_chunks":int,"size_bytes":int}` (`fs_store.py:329`); parse in the **agent** (core has no serde). Add plain `PartMeta` to `apipart.rs` (export from `lib.rs`); `PartSource::part_meta(&self,part) -> io::Result<PartMeta>`; `LocalSsd` impl deserializes a private `MetaJson` (malformed → `InvalidData`/non-benign; missing → `NotFound`/benign). New `PartDrainError::IncompleteSource{declared,present}`, added to `is_benign_deferral` → **defer, not hard-fail** (meta-last ⇒ a hole is a concurrent overwrite, i.e. transient). Guard right after `list_chunks` (`partdrain.rs:338`):
```rust
let meta = ssd.part_meta(part).await.map_err(PartDrainError::io(DrainStep::Persist))?;
let present = u32::try_from(chunks.len()).unwrap_or(u32::MAX);
let complete = present == meta.num_chunks
    && chunks.iter().enumerate().all(|(i,c)| c.get()==u32::try_from(i).unwrap_or(u32::MAX));
if !complete { return Err(PartDrainError::IncompleteSource{declared:meta.num_chunks,present}); }
```
Catches short counts *and* holes (`{0,1,3}` vs 3). **Fixture fix required:** `seed_ssd_part` (`localfs.rs:663`) hardcodes `num_chunks:1` — write `chunks.len()` or every multi-chunk test breaks. *Tests:* `an_incomplete_part_defers_…`, `a_missing_interior_index_is_caught_…`, real-FS `end_to_end_…_overdeclares_defers…`. *Accept:* never commit unless `{0..num_chunks}` all present; truncated part defers, SSD intact, pool empty.

**WI-2 — Interior-chunk full readback** · P1 · folded with WI-3 · `core/partdrain.rs`
Replace the sampled `if Some(index)==first||==last` (`:347`) with an unconditional `chunk_hash` readback+compare for **every** chunk; delete the `(first,last)` line; fix the comment (drop the false content-addressed rationale). *Tests:* replace `…not_caught_by_the_sampled_readback` with `…is_caught_by_full_readback`. *Accept:* a corrupt interior chunk is caught, marks `Failed`, keeps the SSD copy.

**WI-3 — Guard + bounded-retry `mark_failed`** · P2 · folded with WI-2 · `core/store.rs,partdrain.rs` (no migration)
Mirror `mark_replicated`'s guard on `mark_failed`: `… SET status='failed',updated_at=now(),claimed_at=NULL WHERE …AND status='draining' AND claim_seq=$4`; **0 rows = benign no-op** (safe — authorizes no unlink; avoids a `Store` error that would pre-WI-10 trip the breaker; idempotent). Bounded retry in `drain_part`: `const CHUNK_COPY_ATTEMPTS: u32 = 3;` wrap persist+readback; only after exhaustion `mark_failed`+`remove_part`+`ChunkMismatch` (re-persist is safe — atomic tmp+rename). *Tests:* `mark_failed_by_a_fenced_stale_claimant_does_not_fail_the_live_part`, `a_transient_torn_copy_is_recovered_by_the_bounded_retry`. *Accept:* transient recovers; persistent fails after N; fenced claimant can't fail a live part.

**WI-15 — Ancestor-dir fsync** · P2 · ~½d · `agent/localfs.rs` (separate PR)
In `finalize_part` (`:434`), after the part-dir sync, also `sync_parent_dir` the version dir, object dir, and root (idempotent, cheap). Alt: document a CephFS-MDS-journal assumption — but `sync_parent_dir`'s own doc says it's unverified on network mounts, so fsync is the safe default. *Tests:* `finalize_part_fsyncs_the_new_part_version_and_object_dirs`. *Accept:* full ancestor chain fsync'd; e2e drain tests still pass.

**WI-6 — Decay-on-`Err` (R1)** · P1 · ~½d · `agent/runtime.rs`
In `run_alloc`'s `Err` arm (`:280`) apply the same `decay_rate(base,floor,now-allocated_at,half_life)` the `Ok(None)` arm uses (keep the warn). *Tests:* `run_alloc_decays_toward_floor_when_load_allocation_errors` (WI-16 Test 2). *Accept:* rate trends to floor during a Redis outage.

### PHASE 2 (land order: WI-7 → WI-5 → WI-4)
