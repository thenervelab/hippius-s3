## Notes (technical context to keep the list actionable)

[*arch] **Architecture.** Node-local SSD ingest → CephFS pool via the Rust hippius-drain stack (`drain-allocator`
singleton + `drain-agent` DaemonSet). The API writes each part to SSD + `object_versions.address` and **never enqueues
uploads**; the **drain is the sole producer** — once a part replicates it LPUSHes an `UploadChainRequest`, the uploader
ships it to the backend and records `chunk_backend`. State machine `cephor_replication_status`:
`pending → draining → replicated | failed | corrupt`. The janitor evicts a CephFS part only once every required backend
has a live `chunk_backend` row (or the part is terminally abandoned). Cross-node reads in the SSD→pool window use
`DualFileSystemPartsStore` pool fallback. Cutover is flagless (no producer toggle; rollback = image revert). Prod
Postgres is on dedicated NVMe; prod adds dedicated SSD ingest nodes — a full SSD 503s every PUT on that node.

[*shipped] **What shipped (do not redo).** #218 (WI-1…WI-17 hardening) · #220–#225 (worker metrics, observability,
reaper safety, staging reconcile) · #227 (drain throughput throttle — AIMD `TARGET_P99_MS` 50 ms → 2000 ms, the S1
unblocker) · #228 (A7 ETag/order reject) · #230 (A1 cold-fallback DCR) · #231/#232 (lag tune, poll 5 s → 1 s) · #233
durability + #234 coordination, both rolled into **#235** · #236 (read-path A2–A5) · #237 (A6 ACL fallback, A10 DLQ cap,
A12 downloader retry). #235 also added: R4 first-class `corrupt` state + bounded re-drive, C1b/C1c write-side epoch
fence, C2/WI-20 SSD reclaim + orphan-GC, C7/C8/C10/C11/C13, A8/A9/A11/A13/A14/A15/A17/A18/A19/A21, and the WI-19 fault
substrate (mock faults, toxiproxy toxics + redis/PG proxies, noeviction override, Rig A/B, Chaos-Mesh F1–F8 CRDs,
inv-det/inv-guard, durability ledger). **#226 is superseded by #235** (fully contained).

[*c1c] **C1c residual.** `drain-agent/src/runtime.rs` `pull_action` (~line 359) does
`Ok(Some(alloc)) => Adopt(alloc.budget)` with no `StoredAllocation.epoch` comparison. The write-side Lua CAS fence on
`cephor:epoch` is correct; the read-side agent should reject/ignore a stale-epoch alloc key. Pairs with its §4.8
fault-injection test (`C1c epoch-bypass`).

[*nofollow] **O_NOFOLLOW.** No symlink refusal anywhere in the agent/core localfs open path (`grep` = 0). Filesystem
hardening; wider blast radius to validate. Prerequisite for the §4.8 symlink-refused test.

[*a16] **A16.** Post-replication S4 append reaching a backend relies on the drain re-scan (drain-direct). The
"terminally-drained version → SSD-only → lost on reclaim" edge is *mitigated* (not closed) by the R4 servability gate.
File: `append.py`.

[*a20] **A20.** `fs_pressure.py` middleware still uses a single free-space threshold (it got Retry-After ±25% jitter,
not an enter/exit band). The janitor already has hysteresis (elevated 0.85/0.83, critical 0.95/0.93 in
`run_janitor_in_loop.py`).

[*r5] **R5.** Alerts that exist: `drain-split-brain-two-leaders`, `drain-leader-epoch-decrease`,
`aged-pending-orphan-backlog`, SSD backlog/pressure. Missing: a stall alert that fires on `throughput==0 ∧ backlog>0`
derived from SQL/Redis, independent of the lag histogram (a stalled drain emits no lag samples, so the lag SLO reads
healthy). F4 / agent-kill exercises it.

[*load] **Load driver.** Have: boto3 fixed corpus, hardcoded rungs (5/10/20), the durability ledger. Missing:
A1/A2/GB/soak/backpressure/scaling ladders, hold-SLO-for-duration ramp discipline → certified knee, and an in-cluster
GB driver. Fork: boto3-native (self-contained) vs warp/elbencho (spec-literal, external tooling).

[*rust48] **Rust §4.8 tiers.** `loom` tier entirely greenfield (no `loom` dep). Missing proptests: AIMD
multiplicative-decrease/saturation (incl. `error_bps` + `!Open` back-off), `NearFull`-ceiling conservation, 50..1000-node
fleet, epoch `>` vs `≥`. Missing fault-injection (real PG + Redis): concurrent `claim_part` N=2..16, N-way lease,
multi-key all-or-nothing, C1c epoch-bypass, Redis DEBUG SLEEP/black-hole, noeviction-OOM typed Err, fsync EIO,
`O_NOFOLLOW`, two-node same-part, C13 through real faults.

[*r2] **R2 prod-scale gate.** Reaper/reconciler `SELECT`s on prod-sized tables (`multipart_uploads` ~92M / `parts`
~94M) are ~30 s cold / ~478 ms warm, ~3 GB buffers. Gate on **buffers** (no `Seq Scan`, no Hash `Batches>1`) with
`EXPLAIN(ANALYZE,BUFFERS)` at prod scale + HypoPG/Dexter; rewrite predicates as `col = ANY($1::uuid[])`, not
`scalar = ANY(array_col)`. `scripts/gen_clean_dump.py` is absent (doc bug in `CLAUDE.md`).

[*invguard] **inv-guard upgrade.** Today it polls with ≥4× lookbehind + hysteresis; hard binary invariants (two
leaders, unreplicated-chunk delete, byte mismatch, terminal regression) want event-driven log/DB tailing so a fast
violation between polls isn't missed. Fork: trigger+LISTEN/NOTIFY (light) vs logical-decode slot (spec-faithful) vs
log-tail + keep polling.

[*deployorder] **Deploy order.** The drain owns the Rust `cephor_*` schema; the Python migrator owns `schema_migrations`.
Apply: `db-migrations` Job → API/gateway → workers → mpu-reaper. initContainers self-sequence (workers wait on
`wait-for-migrations`; the reaper also waits on `wait-for-cephor-schema`). Then run `tests/smoke` (the staging e2e).

[*initgates] **A18/A19 (done, #235).** mpu-reaper `wait-for-cephor-schema` initContainer
(`to_regclass('cephor_replication_status')`); the four DB workers + reaper have `wait-for-migrations`
(`scripts/wait_for_migrations.py` polls `schema_migrations`). New migration: `object_versions.completed_part_numbers`
(`20260706130000`, nullable → backward-compatible).

[*noeviction] **redis-queues noeviction.** `noeviction` is inert until the process restarts. It holds the work queues
+ pub/sub + `cephor:*` lease/fence keys, so a full instance must reject writes loudly, never evict. Staging e2e is
`allkeys-lru`; the prod-parity override for tests is `stress-test/compose/docker-compose.faults.yml`. AOF reload blips
`cephor:*` — sequence the restart in a window.

[*monfix] **Monitor fix (done, #235 Group 5).** `metrics_collector_task.py` now reads `used_memory`/`maxmemory` from
`redis_queues_client` (was the main redis). Gate on the *instance*, not the `:6382` port (dev-only label; in k8s
redis-queues is a separate host). Just confirm the alert thresholds are set post-deploy.

[*reaper] **Reaper indexes (R2).** Before enabling on prod: (1) run the `20260702000000`
`multipart_uploads(initiated_at)` partial index (not on prod yet); (2) add a composite `parts(upload_id, uploaded_at)`
index; (3) raise `HIPPIUS_MPU_REAPER_INTERVAL_SECONDS` off the 120 s drain-down value. The reaper query also reads
`object_versions.address` — the whole drain stack is staging-only today.

[*gate] **Gate structure.** T1 functional/adversarial · T2 invariant continuous-assertion (`inv-det` + `inv-guard`,
the backbone) · T3 chaos · T4 allocator-under-load (user priority) · T5 throughput/scale/soak. Every dynamic run
(T3/T4/T5) runs on top of T2. Suggested week: Mon SLOs + T1/T2 green; Tue T5 knee; Wed T4 (Scenario C); Thu T3 chaos;
Fri 6h soak + R2 gate.

[*slo] **SLOs (DRAFT — ratify with Ops).** S1 per-node throughput ≥ 200 MB/s at knee (sources disagree 50–200; set CI
floor ~70% of measured p50). S2/S3 replication-lag p99 < 15 s below knee / < 60 s at knee. S4 SSD backlog < 20 GiB/node.
S5/S6 503 < 1% at knee, non-503 5xx < 0.1%. S7 recovery < 120 s. **S8 durability 100% byte-identical** (client-side
plaintext md5 / `x-amz-checksum-*`, NOT ETag) *(non-overridable)*. S9 DLQ growth 0 nominal. **S10/S11 exactly 1 leader,
0 unforced churn** *(non-overridable)*. S12 replication gate 0 unreplicated deletions even ≥95% disk. S13 0 redis-queues
evictions under `noeviction`. S14 6h soak slopes ≈ 0 (incl. `replicated`-still-on-SSD count bounded). Lag = SQL on
`cephor_replication_status (updated_at − landed_at)`; there is no `drain_replication_lag_seconds` metric.

[*invdet] **Running the invariant harness.** `inv-det` (deterministic pre-deploy): `cargo test -p hippius-drain-core`
(**`--include-ignored` + real Redis**), `pytest tests/unit tests/integration`, targeted e2e, static callsite audit,
`trybuild`. **Local drain Rust tests are easy to run wrong** — a bare `cargo test -p hippius-drain-core` silently skips
most: DB tests (`#[sqlx::test]`) need `DATABASE_URL` → Postgres on **:5433** (`postgres:postgres@localhost:5433`); the
system Postgres on :5432 has no `postgres` role (confusing `role "postgres" does not exist`). Coord/tick tests are
`#[ignore]` + need `CEPHOR_TEST_REDIS_URL=redis://localhost:6382/0` and `-- --include-ignored`; `coordination`/`tick`
are behind `--features coord`, `store` behind `--features pg`. Full gate:
`DATABASE_URL=postgres://postgres:postgres@localhost:5433/postgres CEPHOR_TEST_REDIS_URL=redis://localhost:6382/0 cargo test -p hippius-drain-core --features coord -- --include-ignored`.
`inv-guard` guards: G1 single-leader+epoch, G2 replication-gate, G3 durability re-GET, G4 sole-producer, G6 terminal
monotonicity, G9 aged-pending-orphan backlog (G5/G7/G8 covered by inv-det/scenario, honestly reported as `skip`).

[*t4c] **T4 Scenario C = the R3 failover race.** `run_tick` captures `epoch` at lease-acquire, then does slow
`ceiling()` → `write_allocations` with no lease re-read, so a deposed leader (epoch N) that finishes before the
successor (N+1) writes any alloc key lands an epoch-N budget the fence lets through — an agent enforces it, briefly
exceeding the successor's ceiling. **Fixed on #235** (fold the epoch into the Lua CAS conditioned on current
`cephor:epoch`) with a coordination-unit regression + a `run_tick` failpoint test, both fail pre-fix. Scenario C must
still exercise it under *live* failover: successor holds lease, no alloc key written, deposed leader writes epoch N →
stale budget visible ≤ 1 alloc-TTL (15 s) AND ≤ 1 agent poll (2 s), else FAIL. Note the C1c read-side residual above.
Rigs are built (`crates/hippius-drain-allocator/tests/alloc_stress.rs` + `stress-test/alloc-stress/`).

[*chaos] **Chaos F1–F8.** F1 agent-kill mid-replication (resume ≤ 60 s). F2 allocator failover/fence — headline, 3
sub-injections: clean SIGTERM / partition-heal / 2-replica race (single-leader ≤ 45 s partition). F3 redis-queues
blip/evict/hang/noeviction-full (coord ≤ 30 s). F4 CephFS slow/down (breaker ≤ 20 s, no false `replicated`). F5 SSD
fill (clean 503, replication gate absolute). F6 postgres failover (breaker must NOT trip on PG-only fault). F7 clock
skew (disposable pods only). F8 corrupt/partial chunk (never commit corrupt as `replicated`; exercises R4
corrupt→re-drive). CRDs in `k8s/chaos/`, executor in `stress-test/faults/`. F3 needs the noeviction override; F4
IOChaos on CephFS is risky (prefer NetworkChaos toward OSD/MDS).

[*soak] **Soak/knee.** Certify the per-node knee (S1) and hold each SLO for the ramp duration. 6h soak: RSS/FD/pool/
redis slopes ≈ 0 (≤ +2%/h) AND `replicated`-still-on-SSD count bounded (the C2/R1 leak class) AND the aged-pending
orphan count bounded (A21 — the replicated-only gate is blind to it).

[*gonogo] **GO/NO-GO (17 hard gates, any unchecked = NO-GO).** T1 green · inv-det green · inv-guard armed+green all
runs · **S8 durability** · **S10/S11 single-leader** · S12/G2 gate at ≥95% disk · **T4-C (R3)** · chaos F1–F8 · S1–S4

Non-overridable: S8, S10/S11, R3, R4.

[*rollback] **Rollback.** Write path is drain-direct + flagless → rollback = revert images to the prior tag. Migrations

drain is not data loss: acked bytes are on ingest SSD and the janitor's replication gate never evicts an un-replicated
chunk.

[*edge] **Edge auto-caching.** EC-1 must authorize *every* request including cache hits and demote visibility to
`private, no-store` on egress; verify on staging before EC-2/EC-3. Future: edge-validated signed tokens/URLs if per-hit
auth costs too much.
