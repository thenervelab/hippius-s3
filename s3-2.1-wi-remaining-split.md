## Split rationale — vertical ownership, not language

Both engineers are full-stack; the priority is **coherent ownership / quality, not raw parallel speed.** So we split by **coupled vertical**, not by Rust-vs-Python. Two reasons this beats the skillset split:

1. **De-fragments WI-20.** The SSD leak/reclaim story has a hard Python↔Rust interlock (Python marks a row `failed` → Rust reclaims `failed` bytes). A language split scatters that across two people; a vertical split puts the *whole* interlock in one head — zero cross-person handoff on the most coupled fix.
2. **Each person owns one system end-to-end** — "durability / SSD lifecycle" vs "coordination correctness" — instead of scattered pieces of five WIs.

The one thing a vertical split **cannot** parallelize is the chaos gate — it structurally needs both verticals' outputs. So chaos is an **explicit joint Phase 2**, not a lane.

```
Phase 1 (parallel, ~independent verticals)     Phase 2 (joint convergence)
  Vertical A ── durability/SSD lifecycle ──┐
  Vertical B ── coordination correctness ──┴──►  chaos F1–F8 · R2 gate · GO/NO-GO
```

## R3 — the reclassified hard gate (Vertical B / T4)

Was a WI-18 "skip"; **now a prod gate.** `run_tick` (`tick.rs:77-83`) captures `epoch` at lease-acquire, then `load_fleet → ceiling() (slow) → allocate → write_allocations(epoch)` with **no lease re-read**; the Lua fence only rejects against already-written alloc keys. A deposed leader (epoch N) finishing a slow `ceiling()` before the successor (N+1) writes any alloc key lands an epoch-N budget the fence lets through. Every existing fence test seeds the higher epoch first, so this window is never exercised.

**Fix (robustness order):** (1) register the epoch at the resource **at election time**, before any slow work (Chubby-sequencer / etcd `mod_revision`); (2) fold the epoch into the Lua CAS conditioned on current `cephor:epoch`/`cephor:leader`, not last-written value. A bare "re-read before write" is **insufficient** (TOCTOU + lower-token-first). **Test:** failpoint/SIGSTOP at the `ceiling()`→`write_allocations` boundary; elect successor; release; assert the successor **rejected** A's write (assert rejection, not "no corruption").
